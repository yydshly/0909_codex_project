## 核心能力：从 URL 到网页复刻

**输入目标 URL → 浏览器观察与采集 → 分析外观及交互 → 生成组件和页面 → 对照验证 → 交付前端工程。**

目标产物是一份新的前端实现：尽量还原页面布局、字体、颜色、图片、响应式和已观察到的交互，并提供代码继续修改。它并不只是截图保存或网站内容摘要；也不等于恢复原始源码、后台数据库和全部业务系统。

| 输入 | 处理 | 输出 |
| --- | --- | --- |
| 一个或多个可访问的网页 URL，以及任务范围 | 截图、DOM/CSS、素材、交互采集；组件实现和对照修复 | Next.js 页面、组件、路由、素材及验收记录 |

适用于自有网站前端迁移、展示页重建和演示原型。多个 URL 按指定目标处理，不代表自动遍历整站；实际还原效果取决于采集覆盖、模型和工具执行质量。

## 最终理解

**目标、方法、边界应分开：目标是根据 URL 复刻网页；方法是组织模型与工具，通过规格和流程推进；边界是提高稳定性与可检查性，不保证完全可控或穷尽业务。**

1. **模型提供理解与生成，工具提供执行，仓库提供方法。** 本仓库没有训练新模型，没有独立网页理解引擎。
2. **使用截图、运行时 DOM/CSS 和操作记录。** 浏览器 DOM 不等于原始 React/Vue 源码，读取公开页面也不能恢复后台数据库。
3. **事实与推断分开。** 当前尺寸和样式可以测量；设计规范、组件边界和内部交互机制仍可能需要推断。
4. **观察与修正循环推进。** 观察 → 提取 → 分析 → 规格 → 实现 → 验证；发现偏差后返回相应环节。
5. **一致性依靠同一份依据。** 素材、公共样式、接口、状态归属和验收条件贯穿各阶段；多代理主要加速，不自动保证准确。
6. **约束减少随意性，不等于完全可控。** Skill 仍可能被遗漏或误解，构建通过不证明视觉和业务正确。

## 技术原理摘要

**如何识别规范：** 先采集字体、行高、颜色、间距、布局与尺寸，结合可访问 CSS 规则，再跨元素归纳重复样式和结构。这是重建规范，不保证等于原作者设计系统。相近值不能随意合并。

**如何识别响应式：** 多视口采样，发现变化后增加中间样本，区分固定断点、容器查询、自动换行和流式布局，再用未采集过的宽度验证。

**如何识别交互：** 寻找语义、ARIA、焦点和视觉线索，保存操作前状态，执行动作，比较 DOM、样式、内容、URL、焦点与网络变化；重复实验、恢复初始状态。滚动变色不能直接证明使用了 IntersectionObserver。

**如何把控细节：** 先素材与字体，再整体布局，之后局部样式，最后状态和动画。固定浏览器、视口和状态进行截图与行为对照；程序诊断结合人工或模型判断。

完整设计见 [技术说明](notes/technical-understanding.md)，包括结构化证据、任务拆分、状态覆盖和局部修复。
