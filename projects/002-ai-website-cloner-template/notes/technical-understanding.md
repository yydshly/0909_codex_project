# 从 URL 到网页复刻：技术原理与处理思路

## 核心目标与交付结果

输入一个或多个目标 URL，复刻网页的布局、样式、素材、响应式和可观察交互，输出可运行、可修改的 Next.js 前端工程。截图和代码采集是获取依据的手段，规格和验证是控制执行的方法，前端复刻才是最终目标。

主链路：目标 URL → 打开网页 → 采集结构、样式、素材和状态 → 组件与路由实现 → 原站对照 → 前端工程交付。复制外观与可见行为不等于恢复原始源码或后端系统，多个目标 URL 也不等于自动整站爬取。

## 定位与证据等级

基于上游 `92872bc40ced2c5edb4d5dc9fd3970d40c77f4ca` 源码和本次讨论。上游主要通过 Markdown 指令组织代理；下面的结构化采集、状态图、置信度、规格失效和自动门槛，是工程化建议，不能全部算作现有功能。

记录四类结论：**直接读取、操作确认、推断、未知**。每项规则保留来源、视口和状态。看到结果不等于知道原始内部实现。

## 1. 能力如何组成

模型负责理解、归纳、编写与诊断。浏览器提供页面、DOM/CSS、操作与截图；文件和终端工具负责保存、构建与运行。Skill 规定采集、拆分和完成要求，宿主代理运行“模型决定动作 → 工具执行 → 结果回到模型”的循环。

启动 Next.js 只启动前端工程，不会自动启动克隆任务。指令同步脚本转换多平台格式，模型与浏览器连接由外部环境提供。

## 2. 输入与采集

| 输入 | 能说明什么 | 不能直接说明什么 |
| --- | --- | --- |
| 截图 | 外观、构图、区域关系 | 精确规则、隐藏状态与业务 |
| DOM/CSS | 当前层级、文本、样式、尺寸、素材 | 原始组件组织、完整状态逻辑 |
| 操作记录 | 动作对应的可见变化 | 尚未探索的状态、内部算法 |
| 原项目源码（若可获得） | 组件、事件、布局规则和接口调用 | 最终效果仍需运行；服务器数据未必齐全 |

优先利用授权范围内信息最丰富的输入。浏览器运行时代码或打包脚本不等于原始工程。公开页面不能恢复数据库和隐藏业务。

固定 URL、视口、缩放、主题与会话，等待字体及关键图片就绪。分段滚动触发懒加载；结合语义标签、元素坐标和视觉区域建立拓扑。重复结构作为组件候选，不机械保留全部包装 div。

程序保存层级、文本、位置、计算样式、伪元素、素材与状态属性，模型判断语义和需要补看的区域。大页面按区域保存原始快照，向模型传递摘要并按需展开；截断必须记录遗漏。

Shadow DOM、跨域 iframe、Canvas/WebGL、虚拟列表、视频和 Lottie 需要单独处理。DOM 不能直接表达画布内部对象；虚拟列表未显示的内容可能尚不存在。

## 3. 视觉规范与响应式

读取当前样式是测量，命名“正文”“品牌色”“公共容器”是归纳。优先读取可访问 CSS 变量及规则，再统计重复值和结构，结合语义提炼规范。保留原始值和例外，归纳后重新比较外观。

当前宽度 600px 可能来自固定值、父容器百分比、max-width 或网格。比较多个宽度并尽量读取规则才能辨别约束。

先在桌面、平板、手机采样，记录列数、可见性和位置。发现变化后增加区间样本，区分 viewport 断点、容器查询、自动换行和流式尺寸。用未参与采集的中间宽度验收，避免只记住几个截图。

## 4. 交互识别

发现候选元素 → 保存状态 → 执行动作 → 等待并采样 → 比较变化 → 建立状态转换 → 恢复环境。

候选线索包括 button、a、输入框、ARIA、tabindex、cursor 和视觉形态。每种线索都不保证可交互。比较 DOM、属性、样式、文字、URL、焦点和网络；网络观察只帮助理解请求及展示状态，不等于恢复后端。

原创示例：导航从高 88px 变为 64px 并出现阴影。数值仅用于说明方法，不是实测。记录初始、滚动后和返回顶部状态，重复操作排除计时巧合。未读取到事件代码时，只确认外部行为，不断言使用 IntersectionObserver。

菜单需观察开关、Escape、焦点和背景滚动；表单需加载、空值与错误；标签需覆盖各状态内容。设定页面、动作、时间和状态预算，优先主要流程与结构不同状态，避免组合爆炸。线上下单、删除和发送不作为默认探测操作；可在授权测试环境或本地模拟验证。

## 5. 建议的中间描述

| 字段 | 作用 |
| --- | --- |
| elementId / componentId | 关联采集、实现和验收 |
| source / viewport / state | 明确证据条件 |
| rawStyles / bounds / assets | 保存真实读数与素材 |
| layoutConstraints / breakpoints | 说明布局变化规律 |
| states / transitions | 记录动作与结果 |
| props / events / stateOwner | 约定组件连接方式 |
| evidenceLevel / unknowns | 区分事实与推断，保留缺失 |
| specVersion / implementationPath | 追踪代码依赖的规格 |

生成和检查共用这份描述。上游目前主要用 Markdown 规格；结构化契约属于建议。

## 6. 拆分与一致性

先建立字体、主题、容器、类型及通用控件。按独立职责、状态所有权和布局责任拆分：价格区管理月付/年付，卡片接收价格；外层负责排列，卡片负责内部间距。

独立任务并行，依赖任务等待契约确定。公共文件由主代理维护，子代理修改明确归属的文件。Git worktree 隔离工作目录，不自动解决接口或设计冲突。

每个任务带目标路径、导出名、输入、事件、状态归属、依赖、素材、样式、视口、行为和验收条件。规格变更后标记受影响组件并重验，避免代码与依据脱节。

## 7. 验证与修复

素材与字体 → 页面几何 → 局部排版 → 状态与动画。字体错误会改变换行并让整页偏移，应先修根因。

固定浏览器、视口、字体、内容和状态后比较截图。动态时间、广告和动画需要固定或按明确规则排除，同时保留行为测试。像素差、布局差、溢出和文字断言提供客观信号；单一相似度不能证明业务正确。

测量错则重采集，规格错则修规格，实现错则修组件，组件正确但整体错则查集成。限制修改范围并复查相关页面，避免每轮整体重写。

## 8. 完整实现路线（建议）

1. 单页面多视口采集，保存结构、样式、素材、来源和遗漏。
2. 常见菜单、标签、弹窗、滚动行为的可恢复、有预算探索。
3. 结构化规格、公共样式、接口契约、版本和文件归属。
4. 可重复的构建、视觉、交互验收，差异定位和有界修复。
5. 最后扩展路由发现、模板复用、任务队列、断点恢复与并行代理。

## 9. 采用判断

已有代理具备浏览器、编码和验证能力时，可以直接吸收方法，是否引入整库由实际重复任务决定。本次仅归档。

没有生成质量、成本、耗时的对照实验，不承诺还原率或模型优劣。流程能增强可控性，但不保证穷尽隐藏状态，更不能从外观证明后端业务一致。
