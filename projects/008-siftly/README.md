# 008 · Siftly X 收藏知识库

面向个人的自托管 X 收藏知识库，通过文件、Cookie 或官方 API 路径获取收藏，使用 SQLite 存储、视觉大模型提取图片信息，并以全文召回和大模型重排实现自然语言查找；适合工具资料整理、教程检索、视觉素材回找与 Obsidian 积累。

## 我们对这个库的理解

Siftly 是带有前后端的自托管收藏管理应用。它解决的是“已经收藏了很多内容，如何整理并重新找到”的问题。主要流程是：

**获取收藏 → 解析、去重并存入 SQLite → 规则和 AI 补充信息 → 分类浏览与检索 → 导出复用。**

它的价值在于把获取、视觉理解、自动整理、搜索和导出串成一个工作流程。当前代码并不等于已经验证能完整、稳定地获取真实账号的全部历史收藏。

## 接入方式

| 路径 | 用户操作与内部实现 | 当前边界 |
| --- | --- | --- |
| JSON 文件导入 | 在登录的 X 页面用书签按钮或控制台脚本捕获后续网页响应，导出 JSON 后上传 | 两种启动方式共用一种采集原理；可能漏掉已加载内容或提前停止 |
| Cookie 接入 | 提供 `auth_token` 与 `ct0`，程序调用内部 GraphQL，按游标分页；进程内定时器可周期导入 | 登录状态和内部接口会变化；当前同步主要是去重新增 |
| 官方 API | 开发者应用与 OAuth 用户授权，交换 / 刷新令牌，分页获取 | 请求地址与官方文档不一致，分页默认 5 页、最多 20 页；需修正实测 |

真正的数据输入是推文 ID、正文、作者、时间和媒体地址。Cookie 和 OAuth 属于取数凭证。官方 API 有正式授权与分页规范，是更适合长期维护的方向，但不代表仓库现有实现已经可靠。

## 功能与技术原理

| 功能 | 输入 | 内部技术 | 输出 |
| --- | --- | --- | --- |
| 本地存储 | 文件 / 接口返回的数据 | 解析格式、按推文 ID 去重、Prisma 写入 SQLite | 正文、作者、导入数据、媒体信息、分类与状态 |
| 图片理解 | 库内收藏的图片 / GIF，视频主要取缩略图 | 视觉大模型识别文字、物体、场景；SDK 传图，CLI 备用路径仅在提示词中传 URL | OCR 文字、场景和视觉标签，写入媒体记录 |
| 标签分类 | 正文、图片描述、分类说明 | 规则提取实体，大模型生成语义标签、分配分类 | 实体、标签及分类分数；支持增量处理或重跑 |
| AI 搜索 | 用户文字查询、可选分类 | FTS5 / 文本匹配与分类规则召回，再由大模型重排 | 相关收藏、配图、匹配理由与分数 |
| 浏览探索 | 筛选条件、分类操作、库内关系 | 数据库查询、React 页面、React Flow 分类图；另有 CLI 查询 | 列表、网格、分类导图与原文入口；CLI 输出 JSON |
| 导出复用 | 库内收藏、格式及分类 / Obsidian 路径 | CSV / JSON 转换、JSZip 打包、Markdown 模板 | 主要字段导出、分类 ZIP、Obsidian 笔记与索引 |

核心技术栈为 Next.js / React / TypeScript、Prisma / SQLite 和 React Flow。模型适配层包含 Anthropic、OpenAI、MiniMax 路径，具体视觉能力依赖模型支持与访问条件；未看到模型训练或微调实现。

### 图片检索究竟怎么实现

**图片 → 视觉模型生成文字与标签 → 建立全文索引；用户文字查询 → 召回候选 → 大模型重排 → 返回相关收藏。**

它可以用文字描述寻找含相关图片的收藏。OCR 由视觉大模型生成，不是独立 OCR 引擎；当前没有图片向量检索、CLIP 相似度匹配或上传图片找相似图片。视频主要分析缩略图，不能等同于完整视频理解。

搜索依赖候选召回。若目标资料未进入候选集，后续重排无法找回它；当前中文关键词提取会过滤中文字符，纯中文查询可能明显受损。CLI 的搜索是全文 / 文本查询，不执行 AI 重排。

## 使用场景

- **开发者与学习者：** 按技术主题找回收藏过的教程、代码线索和开发工具。
- **工具研究与产品观察：** 分类积累工具发布、功能介绍与行业观点，按用途回找。
- **设计师与内容创作者：** 根据截图文字、图表内容和画面描述查找视觉参考。
- **个人知识管理：** 将 X 收藏导出成带标签、来源与索引的 Obsidian 笔记。

这些是基于现有能力推导的应用场景，不是本次实测结果。它尚不是全网自动采集器、通用文档问答服务或团队协作系统。

## 数据与导出边界

- 媒体地址入库，不代表媒体已经下载到本地。
- JSON / CSV 导出主要字段，不包含完整数据库及全部 AI 分析字段。
- 分类 ZIP 含清单和成功下载的媒体；全量 ZIP 仅包含 JSON。
- Obsidian 笔记有分类、作者索引，但媒体仍引用远程地址。
- 思维导图展示分类归属，不推理书签之间的观点、引用或因果关系。
- 本地部署可以保存数据；使用外部 AI 服务时会发送相关文本和图片。

## 优先补充与优化

1. **可靠获取：** 修正官方 API 请求，完善分页续传、限流重试，区分正常完成、达到上限与失败停止。
2. **内容完整性：** 验证长推文、线程、引用与媒体保存范围，明确新增同步和双向同步的区别。
3. **检索质量：** 修复中文处理，用有已知答案的问题评估召回和排序，再决定是否增加混合向量检索。
4. **运行与复用：** 持久化任务状态、记录费用；进一步增加带引用问答和更多来源。

以上为研究建议，未在上游应用中实施。
