IV-ORG / INVIDIOUS

自己的观看入口，
视频仍来自 YouTube。

Invidious 获取并整理 YouTube 内容，用自己的网页展示和播放，再提供独立的账号、订阅与 API。它是一套可以自建的服务。

先记住这三件事

01

内容来自 YouTube搜索结果、频道信息和视频流，主要由 YouTube 提供。

02

账号数据属于你的实例订阅、历史与偏好由 Invidious 保存，独立于 Google 账号。

03

播放需要专门适配Companion 处理播放会话与视频流，能搜索不代表一定能播放。

03 / 我们澄清过的概念

“内部接口”不代表内部员工权限。

这里的“内部”指 YouTube 自己的网页和 App 使用。开发者可以观察客户端请求、分析参数与返回结构，Invidious 将自己的调用实现公开在源码中。

YouTube → 第三方开发者

YouTube 官方开放 API

面向第三方提供正式文档，按官方要求申请使用。

Invidious 没有以这套 Data API 作为内容获取路径。

YouTube → 自己的网页 / App

YouTube 内部接口

为客户端提供搜索、频道、播放等数据。可分析请求，但没有面向第三方的稳定使用承诺。

Invidious 负责适配这部分协议与响应。

Invidious → 你开发的应用

Invidious 对外 API

把内容整理成公开文档中的字段和接口。开发自己的客户端，可以从这里接入。

读取内容；认证后管理实例中的用户数据。

同一个关键词，两种输出。

网页与 API 共用业务逻辑，网页不需要先请求一遍自己的公开 API。

给人看
/search?q=做饭返回搜索页面
给程序用
/api/v1/search?q=做饭返回 JSON 数据

04 / 六组实际能力

它为使用者和开发者分别做好了什么？

01

搜索与频道浏览

搜索视频、频道和播放列表；浏览频道视频、Shorts、直播及社区等入口。

数据来源
YouTube；路由存在不代表上游当前一定可用。
02

观看、听音频与嵌入

提供播放器、音频模式、DASH 等路径，并支持嵌入页面和下载入口。

谁负责播放
主服务与 Companion 配合；增强播放依赖 JavaScript。
03

视频信息、字幕与评论

整理标题、作者、描述、字幕、文字稿和评论。评论另有 Reddit 来源。

能力边界
获取已有内容，不内置语音识别或 AI 总结。
04

独立账号与订阅

保存订阅、历史、偏好和播放列表，提供导入导出能力。

保存在哪里
实例的 PostgreSQL；不会自动修改 Google 账号。
05

缓存与更新聚合

缓存视频信息，后台刷新频道，预先整理用户的订阅内容，提供 RSS 等入口。

为什么需要数据库
管理状态和元数据；并非保存整个视频文件库。
06

供其他应用调用

提供视频、搜索、频道、字幕、评论等 API，以及需认证的用户管理接口。

怎样复用
开发手机、电视或学习客户端，不必自己处理所有上游协议。

05 / 能力边界

理解它能做什么，也理解它依赖什么。

视频来源可以改成本地文件或 B 站吗？

没有通用视频源开关。内容模型、频道结构和播放流程围绕 YouTube 编写。接入其他来源，需要另行开发适配与播放逻辑。

自己的服务器会保存所有视频吗？

不会。数据库主要保存账号、订阅和部分视频信息。代理视频是转发媒体流，不等于完整归档；项目也不是视频上传托管平台。

为什么能搜索却不能播放？

搜索和播放经过不同链路。Companion 会话、临时地址、上游访问限制或媒体传输任一环节失败，都可能导致播放失败。

不需要官方 API Key，就能无限调用吗？

不能。YouTube 的接口变化、限流和封锁仍会影响实例。网站或健康检查可访问，也不能证明每个视频都可播放。

自建后就完全匿名、自动去掉所有广告了吗？

隐私取决于视频是否直连和实例日志等配置；运营者可能记录访问。项目提供无广告界面，但不能理解为自动删除视频中创作者自行植入的商业内容。

架构带来的实际代价

适配省下的工作，
会转化为维护责任。

  • 上游变化YouTube 改接口或限制访问，需要更新适配。
  • 播放流量代理视频后，实例要承担媒体传输带宽。
  • 后台更新频道刷新和订阅聚合持续消耗网络与数据库资源。
  • 运行条件基础组合有主服务、Companion 和数据库；本次未安装运行。

06 / 基于现有能力的扩展

先复用内容能力，再开发自己的产品。

下面是架构推导的应用方向，不是已内置功能。

语言学习工具

复用：视频、字幕、播放。
新增：双语排版、生词本、练习和学习进度。

视频知识库 / AI 摘要

复用：元数据和已有字幕。
新增：分段、模型处理、检索与时间戳引用。

频道更新简报

复用：频道列表、订阅数据或 RSS。
新增：调度、去重、摘要和通知。

专用客户端

复用：对外 API 和播放资源。
新增：电视、手机或适老界面及兼容处理。
