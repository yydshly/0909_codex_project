定位、目标与适用场景

本次的定位判断：Archify 是面向 Agent 的技术图表达、校验与交付工具链。它以 Skill 指导表达，以有类型的 JSON 保存图模型，以程序渲染和校验，交付独立 HTML 查看器。适合系统讲解、代码研究、设计评审、文档维护和架构变更沟通。

核心价值是让图规格可以复查、修改和版本化，让产物可以交付与阅读。直接使用者可以是用户、Agent 或提供结构化规格的外部工具；已生成页面的阅读与导出不需要在线大模型。

与我们研究过的 Lieflat Charts 相比，Archify 侧重技术系统的结构、关系和过程，后者侧重数据、指标与报告图表。

查看器还提供搜索、聚焦、上下游可达范围、有向路径查询、章节讲解、地图与语义分类阅读、动画和演示模式。视觉上有 Classic、Signal Flow、Blueprint、Editorial 四种预设及深浅主题。交付及导出包括 HTML、PNG、JPEG、WebP、SVG、WebM 和三种分享卡片；剪贴板取决于浏览器权限。这些不是新的图型，各视图的操作有所区别。

输入是什么，原理是什么？

源码 / 描述 / 文档 / Mermaid → 用户或 Agent 理解 → JSON 图规格 → 校验与渲染 → HTML 查看器。
程序直接消费图规格 JSON。源码不会自动变成图中关系；大模型也不是绘制已有规格的必需依赖。

  1. 确定内容：作者选择问题、图型、关键对象、关系与阅读层级，Skill 提供表达和工作流指导。
  2. 建立规格：声明节点、关系、布局、说明卡片和章节；不同图型有专门 Schema。开发阶段用 AJV 编译校验器，运行时使用生成的校验逻辑。
  3. 加载校验：检查字段、引用、关系标识与相关约束。架构图可核验 Git 提交、仓库地址、文件和行范围；这不等于验证分析结论。
  4. 布局渲染：五类渲染器处理各自布局；共享模块处理几何、路由、样式、模板和诊断。生成 SVG，再与元数据和资源装入 HTML。
  5. 受控交付：deliver 冻结输入，在私有目录生成候选，运行产物检查，计算 SHA-256，成功后原子替换最终文件。提交前失败清理候选；有旧产物则保留它。
  6. 查看迭代：浏览器沿规格中的关系探索。preview 监控输入、触发重建，通过验收才更新，失败时保留上次成功图。

原生源码核验目前用于架构图。其余图的代码依据在实战页另列表说明。此分析版本把 JetBrains Mono 字体字节内嵌进查看器 HTML，中文仍用系统字体回退。

真实演示与架构差异

Archify 自身实战 的五类中文图描述核心模块、交付职责、进程交互、数据形态及产物阶段。五张图各通过 9/9 原生产物检查和 showcase 构图校验，零错误、零警告；另验证八组风格、八份导出、源码链接、有向路径及下游追踪。

预览实验实际经历“有效输入 → 损坏 JSON → 修复”：失败时状态为 needs-fix，产物哈希和版本号不变；修复后交付第二版。这是保存的实验记录，不是网页背后始终运行着实时服务。

真实架构差异：相邻提交 b86b607 → 1072200 把在线 Google Fonts 依赖改为内嵌资源。Before 看变更前，Delta 看差异，After 看变更后。两个新增和两个删除分别包含一个节点及其连线，模板还有一处修改。比较对象是本次按代码编写的两个架构 JSON，均由当前渲染器生成，并非比较器自动理解了 Git diff。

实测问题：本次 Chrome 的工具栏操作会清除聚焦，键盘确认也未完成范围分享。路径／范围卡片通过原生 Archify.exportMenu 方法生成，没有改写上游实现。检查不覆盖所有输入、浏览器与异常条件。

软件工程体系如何组织这些图？

完整设计需要关注点、层级、语义和理由。图的数量不等于完整性；同一条交付链换五种视角，仍可能没有深入模块。

体系本质设计作用
UML统一建模语言定义元素和关系的语义。结构类包括类、对象、包、组件、组合结构、部署、轮廓；行为类包括用例、活动、状态机，以及顺序、通信、交互概览、定时等交互图。
4+1架构视图模型逻辑看职责与抽象，开发看源码组织，进程看并发通信，物理看部署；关键场景作为“＋1”贯穿并验证四者。一种视图可以用多张图表达。
C4架构分层表达系统上下文 → 容器 → 组件 → 代码，逐层进入细节。容器指应用、服务或数据存储等单元，不专指 Docker；另有动态与部署等视图。
arc42架构文档模板组织目标、约束、上下文、结构、运行、部署、决策、质量要求和风险，补上图之外的设计依据。
BPMN / SysML专门建模语言BPMN 面向业务流程、事件与协作；SysML 面向含软件、硬件等要素的系统工程。
ArchiMate / TOGAF企业建模语言 / 企业架构框架ArchiMate 连接业务、应用和技术；TOGAF 提供架构方法和治理框架。

分层、微服务、事件驱动、六边形架构属于系统组织方式。建议用 C4 组织深度，用 4+1 检查关注点，用必要的 UML 或专门图型表达细节，用 arc42 保存完整设计理由。

扩展路线与优先级

  1. 数据来源：接入依赖和调用分析、数据库、部署配置、接口描述和运行追踪；保留版本、来源、推断和未知项。
  2. 模型语义：先定义新图型 Schema 和语义，再增加布局、渲染、诊断和验证；方框模拟类图外观不等于支持类图。
  3. 阅读体系：用稳定 ID 关联全景、模块与实现，提供跨图跳转、按场景阅读、变化和测试证据，形成可维护图谱。

Archify 自身优先补充：模块依赖图、关键函数调用图、五类规格结构图、预览状态机、新图型接入图。它们属于后续建议，当前展厅没有冒充已完成这些深入分析。

图校验不证明整个系统正确；引用有效不证明关系语义正确；图上可达不等于生产故障影响；增加图型不自动带来数据来源；详细程度取决于问题、分析质量和层级拆分。
